# מפות אופליין — OsmAnd &amp; מובידוס

אתר GitHub Pages להורדה חופשית וללא הגבלה של מפות אופליין עבור OsmAnd ונתוני מובידוס.

## מבנה הפרויקט

```
index.html                              דף הבית
privacy-policy.html                     מדיניות פרטיות
js/app.js                               לוגיקת הצד-לקוח (חיפוש, הורדות, מודאלים)
data/osmand-data.json                   קישור + תאריך עדכון לכל קובץ obf (נכתב אוטומטית)
data/moovitdos-link.json                קישור לקובץ הנתונים העדכני של מובידוס (נכתב אוטומטית)
data/update-status.json                 מצב הריצה האחרונה (בינארי: תקין/שגיאה) (נכתב אוטומטית)
data/tag-rule-data.json                 "מסד הידע" הגיאוגרפי — מדינות, יבשות, ואזורים (ר' למטה)
data/mapsTags.json                      תגיות geo לכל קובץ, נגזרות ממסד הידע (נכתב אוטומטית)
update-scripts/osmand_filename.py       פענוח שמות קבצים משותף לשני סקריפטי התגיות
update-scripts/data-update.py           מוצא/מעדכן קישורים ל-OsmAnd + מובידוס
update-scripts/tag-rule-generator.py    קובץ 1: ממלא פערים במסד הידע באמצעות Gemini
update-scripts/tag-generator.py         קובץ 2: בונה מחדש את mapsTags.json — לוגיקה טהורה, ללא AI
.github/workflows/update-pipeline.yml   הרצה אוטומטית 4 פעמים ביממה (וגם ידנית) — שלושת השלבים
.github/workflows/manual-*.yml          שלוש הרצות ידניות נפרדות, אחת לכל סקריפט
```

## איך זה עובד — קישורים לקבצים (`data-update.py`)

התפקיד היחיד של הסקריפט הזה הוא למצוא קישור עבודה לכל קובץ — לא בהכרח לארח כל קובץ בעצמנו:

- **git חוסם קבצים בודדים מעל 100MB לצמיתות**, וחלק ניכר מקבצי OsmAnd (מדינות שלמות)
  גדולים בהרבה מזה. לכן קובצי ה-obf **לא נשמרים ב-git** — הם מועלים כ-Assets על
  GitHub Release ייעודי בתוך המאגר הזה (Assets תומכים בקבצים עד כ-2GB, ולא משפיעים
  על גודל ה-push של git כלל).
- **מדיניות אירוח לפי גודל**: רק ישראל, פלסטין (יו״ש), או קובץ שגודלו הדחוס (כפי
  שמפורסם ישירות ב-`list.php` של OsmAnd) הוא מתחת ל-40MB — הם מועמדים להעלאה
  ל-Release שלנו. כל שאר הקבצים **אף פעם לא מורדים בכלל** לצורך הבדיקה הזו (הגודל כבר
  ידוע מראש), ומקושרים תמיד ישירות ל-zip המקורי של OsmAnd. זה שומר על ה-Release קטן
  ומהיר, ועל כל ריצה קלה במיוחד. קובץ שהיה מאורח בעבר ואינו עומד עוד בקריטריון (למשל
  אחרי שינוי מדיניות, או גדל בגרסה עתידית) — ה-Asset שלו נמחק וההפניה חוזרת ל-OsmAnd.
- **לכל קובץ יש קישור עבודה תמיד**, גם אם ההעלאה לא הצליחה/לא הספיקה בזמן/לא הייתה
  מועמדת מלכתחילה: אם ההעלאה ל-Release מצליחה, `url` מצביע על קובץ ה-obf שלנו
  ו-`"zip-osm-file": false`. אם לא — `url` מצביע ישירות על קובץ ה-zip המקורי של
  OsmAnd, ו-`"zip-osm-file": true`. שדה `originalZipUrl` תמיד מכיל את קישור ה-zip
  המקורי, ללא קשר לסטטוס האירוח, כדי שכפתורי ישראל/יו״ש (ר' למטה) יוכלו להסתמך עליו
  ישירות — אך הם **מעדיפים** את הגרסה המחולצת שלנו כשהיא זמינה, ורק נופלים חזרה
  ל-zip המקורי (עם הודעת החילוץ) כשאין ברירה.
  - **לא נחשב שגיאה** אם חלק מהקבצים לא הועלו — רק גישה כושלת ל-OsmAnd עצמו (`list.php`)
    נחשבת שגיאה (`osmand-status: false`). אין יותר מצב "מתעדכן" — הסטטוס בינארי בלבד.
  - קבצים מועמדים (ישראל/פלסטין או מתחת ל-40MB) ש-`zip-osm-file` שלהם `true` מנוסים
    שוב בכל ריצה, כך שהם משתדרגים לאירוח שלנו ברגע שיש תקציב זמן/גודל פנוי.
- **סדר עדיפות**: ישראל ופלסטין (יו״ש) תמיד ראשונים, ואז שאר הקבצים לפי גודל — מהקטן
  לגדול — כדי למקסם כמות קבצים מטופלים בכל ריצה בתוך התקציב.
- **מחיקה**: אם OsmAnd הסירו קובץ מהרשימה שלהם, וה-fetch של `list.php` עצמו הצליח (לא
  שגיאת רשת/פרסור), הקובץ מוסר מ-`osmand-data.json` וה-Asset שלו (אם היה) נמחק
  מה-Release. תגיות/מידע במסד הידע **לא** נמחקים, למקרה שהקובץ יחזור.
- **תקציב זמן פנימי**: 8 דקות, מתחת ל-`timeout-minutes: 10` של ה-job — כדי שהסקריפט
  תמיד יסיים ריצה רגילה (ויאפשר commit) ולא ייחתך באמצע.
- מובידוס: פנייה ישירה ל-API האמיתי של `moovitdos/moovidos/releases` (לא ניחוש/scraping),
  עם `GITHUB_TOKEN` המובנה לצורך קבלת מכסת קריאות מאומתת (5,000/שעה במקום 60).
  
### מבנה תגית (`geo` array)

כל קובץ מקבל מערך
`geo` גמיש, מהרמה הרחבה ביותר לספציפית ביותר — ורק ברמות שבאמת ידועות:

```json
{
  "fileName": "Canada_british-columbia_alberni-clayoquot_northamerica_2.obf",
  "geo": [
    {"en": "North America", "he": "צפון אמריקה"},
    {"en": "Canada", "he": "קנדה"},
    {"en": "British Columbia", "he": "קולומביה הבריטית"},
    {"en": "Alberni-Clayoquot", "he": "אלברני-קלייקווט"}
  ],
  "emoji": "🇨🇦"
}
```

## זרימת GitHub Actions

- **`update-pipeline.yml`** — רץ אוטומטית 4 פעמים ביממה (כל 6 שעות), וגם ידנית.
  שלושה jobs:
  1. `update-links` (`data-update.py`) ו-`update-tag-rules` (`tag-rule-generator.py`)
     רצים **במקביל** (שני jobs נפרדים, לא תלויים זה בזה), כל אחד עם timeout של 3 שעות.
  2. `rebuild-tags` (`tag-generator.py`) רץ **אחרי ששניהם הסתיימו** (`needs`), עם
     timeout של 15 דקות בלבד (הוא לוגיקה טהורה ומהיר מטבעו).
  - שני ה-jobs המקביליים עלולים לדחוף (push) בו-זמנית; שלב ה-commit בכל job כולל
    ניסיון חוזר עם `git pull --rebase` למקרה שה-push הראשון נדחה.
- **`manual-data-update.yml`**, **`manual-tag-rule-generator.yml`**,
  **`manual-tag-generator.yml`** — הרצה ידנית בלבד של סקריפט בודד, לבדיקה/דיבוג.

## הערות נוספות

- **הודעת חילוץ ZIP**: כשמשתמש מוריד קובץ שעדיין רק על OsmAnd (`zip-osm-file: true`),
  נפתח מודאל שמסביר שיש לחלץ את הקובץ לפני ההעתקה לטלפון. כפתורי ישראל/יו״ש **מעדיפים**
  את הגרסה המחולצת שלנו כשהיא זמינה (ואז אין הודעה) — הם מציגים את ה-zip המקורי של
  OsmAnd (עם ההודעה) רק כשאין לנו עדיין גרסה מחולצת. המודאל נסגר אוטומטית אחרי 7
  שניות או בלחיצה על "סגור כעת". המודאל **אינו** נפתח עבור הורדות מובידוס.
